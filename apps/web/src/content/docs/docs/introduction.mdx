Aura finds configuration drift between the coding agents on your machine and gives you one safe
plan to repair it. Use it when Claude Code, Codex, and Cursor should share instructions, skills,
and MCP servers without maintaining the same configuration three times.

## The problem Aura solves

Imagine a repository with these three states:

| Application | Instructions              | Skills               | MCP servers    |
| ----------- | ------------------------- | -------------------- | -------------- |
| Claude Code | Loads the team rules      | Has `review`         | Has GitHub     |
| Codex       | Loads an older rules file | Missing `review`     | Has GitHub     |
| Cursor      | Loads no shared rules     | Has a stale `review` | Missing GitHub |

Aura reads each application's configuration into one model and reports the differences. When a
finding can be repaired, Aura builds a file plan, shows it to you, and waits for confirmation.

:::note[The short version]
Aura is a configuration doctor, not another coding agent. It helps the agents you already use
agree on shared instructions, skills, and MCP servers.
:::

## What Aura writes

Aura manages personal configuration below `~/agents` and the global configuration of applications
you select. It may inspect repository files for diagnostics, but setup, fixes, and undo do not
modify the current repository.

Every write goes through the same safety path:

1. Aura reads and validates the current files.
2. It shows one combined plan; add `--detail` when you need the complete diff.
3. It checks that the files did not change after the preview.
4. It writes atomically and records a backup for `aura undo`.

:::caution[Plugins are trusted code]
Plugins run with the privileges of the Aura process. Install a plugin with the same care you apply
to any other dependency. Aura makes plugin fixes previewable; it does not sandbox plugin code.
:::
